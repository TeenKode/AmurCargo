# ПОГРУЗЧИК

Проект для кейса КнААЗ: найти груз на одном радиальном поле, поднять его и перенести в зону второго круга.

## Начать работу

Для быстрого запуска скачайте **[OFFLINE.html](OFFLINE.html)** и откройте в Chrome или Edge. В одном файле доступны 3D-симулятор, сборка, список покупок, краткое руководство и калибровка. Веб-сервер и интернет не нужны. Для получения исходников, STL и прошивки также можно скачать весь репозиторий: **Code → Download ZIP**, распаковать и открыть `START.html`.

- [Общий автономный HTML](OFFLINE.html) — все пользовательские разделы в одном файле, переключение без перезапуска симуляции.
- [3D-симулятор](simulator/Open_Simulation_3D.html) — один HTML без сетевых зависимостей.
- [Сборка и подключение с картинками](simulator/Assembly_Guide_RU.html) — 10 шагов, 7 видов текущей модели и 8 схем.
- [Покупки и предоставленный набор](simulator/Purchase_List_RU.html).
- [Короткий список покупок с количествами](Shopping_short.txt).
- [Единственные исходники прошивки](firmware/RadialRobot) — Arduino и общий алгоритм; WASM-обёртка хранится в `firmware/wasm`. Сборочные образы формируются в `firmware/build`.
- [Как пересобрать проект](BUILD.md).
- [Схема L298P Shield + SG90 + HW-511](hardware/L298P_SHIELD_RU.md) — распиновка, питание, решение конфликта таймеров.

GitHub показывает исходный текст HTML. Для запуска откройте скачанный файл в Chrome или Edge. GitHub Pages отдельно не включён. После успешных проверок GitHub Actions автоматически обновляет в ветке проверенные образы `firmware/build/`, `simulator/Open_Simulation_3D.html` и объединённый `OFFLINE.html` из общих исходников. Для незавершённых PR используйте файлы соответствующей ветки, а не `main`.

## Возможности

- Редактирование размеров поля на карте, выбор груза и зоны разгрузки.
- Автоматический поиск, захват и доставка; лежащая и стоящая гантель.
- Ручные проверки вил, короткие движения, замеры пути и поворота, подгонка модели по реальным результатам.
- UNO / Nano ATmega328P, загрузка через Web Serial и скачивание полного проекта Arduino с текущими настройками.
- Отдельное управление настоящим роботом по USB, калибровка датчиков и сохранение направления SG90 в EEPROM.
- Облегчённая спинка с плоской задней стороной и съёмные лапы на боковых М3×16. Цельная качалка R18: гайка приводного винта с обратной стороны; втулка 4 / 3,2 × 10,5 мм.

## Печать

Актуальные файлы перечислены в инструкции. Основные STL находятся в `mechanics/Print_Ready`; новые съёмные вилы — в `mechanics/Fork_Adapters`, качалка и пробник — в `mechanics/Servo_Horn`.

Для вил берите файлы `*_Print_Orientation.stl`. Из четырёх посадок качалки печатается одна после примерки пробника. STEP в `Print_Parts` — редактируемые исходные заготовки; это не дополнительный комплект для печати.

## Текущая электроника

В экспериментальной ветке L298P: два TT-мотора, **RB L298P Motor Shield**, SG90 через Timer0, три фоторезистора, кнопка запуска A3 с подтяжкой и HW-511 на D2 (вход без подтяжки, активный HIGH по умолчанию; полярность/подтяжка регулируются через USB) для обнаружения груза. Поддерживается ATmega328P / 16 МГц. Нужны отдельные проверенные источники питания моторов и SG90 и общий GND. Схема и последовательность подключения находятся в иллюстрированной инструкции.

## Прошивка при подключённом COM-порте

В разделе «Arduino» → «Прошивка» кнопка «Записать программу по USB»
доступна даже при работающем мониторе порта. При нажатии интерфейс
автоматически завершает чтение/запись монитора, освобождает COM-порт
и предлагает выбрать Arduino для загрузки. Выберите тот же COM-порт в
системном диалоге браузера; при необходимости снова подключите монитор
после записи. Порт нельзя использовать одновременно для мониторинга и
работы загрузчика. Если браузер не поддерживает Web Serial или страница
открыта в небезопасном окружении, используйте Chrome/Edge и отдельный
HTML-файл симулятора или Arduino IDE с экспортированным ZIP.

## Испытание движения по линии на настоящем роботе

После обновления прошивки повторите калибровку всех трёх фоторезисторов:
- при «белом» образце все три датчика должны целиком находиться над белым;
- при «чёрном» образце — целиком над большим чёрным участком (не на кромке линии);
- при движении средний датчик находится над линией, а боковые могут смотреть на границу чёрного и белого.

В новой версии убрано обнуление PWM L298P на каждом проходе цикла,
добавлена медиана трёх последовательных показаний (подавляет единичные
всплески), уменьшена предельная коррекция и предотвращена команда слишком
малой мощности внутреннему колесу при нормальном слежении за линией.
Стартовые коэффициенты — только отправная точка для физических испытаний.

Разворот после погрузки теперь требует, чтобы центральный датчик сначала
перестал видеть линию не меньше 40 мс, а затем **снова** устойчиво увидел
узкую линию в течение `TURN_LINE_MS`. Минимальный таймер уменьшен с 2050
до 500 мс (с грузом с 2320 до 600 мс); максимальный таймер составляет
2800/3300 мс. Если линия не обнаружена, робот прекращает вращение с
ошибкой `TURN_TIMEOUT`, а не бесконтрольно вращается дальше.

Эти времена следует проверить и при необходимости изменить под
фактическую скорость вращения. Проверьте разворот без груза и с грузом на
вывешенных колёсах, затем на поле. Если линия обнаруживается раньше,
чем прошёл реальный разворот 180°, увеличьте минимальное время; если
робот доходит до 180° раньше, но не останавливается, проверьте показания
`line` / порог `LINE_THRESHOLD` / правильность калибровки. При
`TURN_TIMEOUT` проверьте минимальное/максимальное время и контраст
полосы, а не бесконечно увеличивайте таймер.

Диагностика через USB: `stream on` и `status` выводят
`raw`, `line`, `err`, `corr`, `pwm` и `target`.
Прошивка использует новые настройки только после записи обновлённого
образа. **Нужны реальное полевое испытание и корректировка параметров;
автоматические тесты не подтверждают точность 180° на конкретном шасси.**

## Что проверено

Проверены сборка прошивки для UNO и Nano, автоматические сценарии, ручное управление и экспорт настроек, соответствие встроенных моделей STL и геометрия исправленного узла качалки. C++-адаптер оборудования исполнялся в AVR-эмуляторе с моделями GPIO, EEPROM и серво. Физическая загрузка через браузер и грузоподъёмность ещё требуют испытаний на настоящем роботе.

Симуляция приближённая: она не рассчитывает прочность, массу, сцепление колёс и реальные оптические свойства поля. Поле по картинке — схема для настройки, а не подтверждённые размеры конкурсного поля.

## Исходные материалы

`references` содержит предоставленные материалы кейса и фото. `mechanics/User_Models` — исходное шасси пользователя, `Downloaded_Models` — использованные библиотечные модели. Источники и условия сторонних материалов перечислены в `THIRD_PARTY.md` и `mechanics/SOURCES.md`.


## Структура проекта

- `simulator/` — готовый веб-симулятор, его настройки и страницы инструкции и закупок.
- `firmware/` — проект Arduino, включая общий алгоритм движения.
- `mechanics/` — основные STL в `Print_Ready/`, исходники CAD в `Print_Parts/` и модели поставщиков.
- `references/` — документы кейса и фотографии.
- `tools/` — генераторы, исходники интерфейса и проверки.
- `outputs/` — локальные архивы после сборки.

Команда `python tools/package_full_project.py` создаёт ZIP из текущего коммита.

## Единый автономный HTML

`python tools/rebuild_site.py` пересобирает прошивку, страницы и `OFFLINE.html` из актуальных исходников. Для пересборки только оболочки после обновления HTML-страниц: `python tools/build_offline_all.py`. Нельзя редактировать `OFFLINE.html` вручную: это генерируемый файл. Он загружает страницы во встроенных фреймах по требованию и сохраняет их состояние при переключении вкладок; отдельные страницы можно скачать из верхней панели. Внешние ссылки на производителей требуют интернета. Для Web Serial нужен поддерживающий браузер; при ограничениях доступа из фрейма скачайте исходный HTML симулятора кнопкой «Скачать раздел отдельно».
