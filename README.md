# ПОГРУЗЧИК

Проект для кейса КнААЗ: найти груз на одном радиальном поле, поднять его и перенести в зону второго круга.

## Начать работу

Для быстрого запуска скачайте **[OFFLINE.html](OFFLINE.html)** и откройте в Chrome или Edge. В одном файле доступны 3D-симулятор, сборка, список покупок, краткое руководство и калибровка. Веб-сервер и интернет не нужны. Для получения исходников, STL и прошивки также можно скачать весь репозиторий: **Code → Download ZIP**, распаковать и открыть `START.html`.

- [Общий автономный HTML](OFFLINE.html) — все пользовательские разделы в одном файле, переключение без перезапуска симуляции.
- [3D-симулятор](simulator/Open_Simulation_3D.html) — один HTML без сетевых зависимостей.
- [Сборка и подключение с картинками](simulator/Assembly_Guide_RU.html) — 10 шагов, 7 видов текущей модели и 8 схем.
- [Покупки и предоставленный набор](simulator/Purchase_List_RU.html).
- [Короткий список покупок с количествами](Shopping_short.txt).
- [Единственные исходники прошивки](firmware/RadialRobot) — Arduino и общий алгоритм; WASM-обёртка хранится в `firmware/wasm`. Сборочные образы формируются в `firmware/build`.
- [Как пересобрать проект](BUILD.md).
- [Схема L298P Shield + SG90 + HW-511](hardware/L298P_SHIELD_RU.md) — распиновка, питание, решение конфликта таймеров.

GitHub показывает исходный текст HTML. Для запуска откройте скачанный файл в Chrome или Edge. GitHub Pages отдельно не включён. После успешных проверок GitHub Actions автоматически обновляет в ветке проверенные образы `firmware/build/`, `simulator/Open_Simulation_3D.html` и объединённый `OFFLINE.html` из общих исходников. Для незавершённых PR используйте файлы соответствующей ветки, а не `main`.

## Возможности

- Редактирование размеров поля на карте, выбор груза и зоны разгрузки.
- Автоматический поиск, захват и доставка; лежащая и стоящая гантель.
- Ручные проверки вил, короткие движения, замеры пути и поворота, подгонка модели по реальным результатам.
- UNO / Nano ATmega328P, загрузка через Web Serial и скачивание полного проекта Arduino с текущими настройками.
- Отдельное управление настоящим роботом по USB, калибровка датчиков и сохранение направления SG90 в EEPROM.
- Звуковая индикация L298P D4: этапы работы, погрузка, выгрузка, остановка, ошибки; команды `buzzer test|on|off|status` и EEPROM.
- Облегчённая спинка с плоской задней стороной и съёмные лапы на боковых М3×16. Цельная качалка R18: гайка приводного винта с обратной стороны; втулка 4 / 3,2 × 10,5 мм.

## Печать

Актуальные файлы перечислены в инструкции. Основные STL находятся в `mechanics/Print_Ready`; новые съёмные вилы — в `mechanics/Fork_Adapters`, качалка и пробник — в `mechanics/Servo_Horn`.

Для вил берите файлы `*_Print_Orientation.stl`. Из четырёх посадок качалки печатается одна после примерки пробника. STEP в `Print_Parts` — редактируемые исходные заготовки; это не дополнительный комплект для печати.

## Текущая электроника

В экспериментальной ветке L298P: два TT-мотора, **RB L298P Motor Shield**, SG90 через Timer0, три фоторезистора, кнопка запуска A3 с подтяжкой и HW-511 на D2 (вход без подтяжки, активный HIGH по умолчанию; полярность/подтяжка регулируются через USB) для обнаружения груза. Поддерживается ATmega328P / 16 МГц. Нужны отдельные проверенные источники питания моторов и SG90 и общий GND. Схема и последовательность подключения находятся в иллюстрированной инструкции.

## Управление роботом по COM

В `OFFLINE.html` откройте «3D-симулятор» → **«Робот · USB»**. Нажмите «Подключить» и выберите COM-порт Arduino. «Стоп» доступен в верхней панели. Кнопки разделов ведут к пробам колёс, сервоприводу, датчикам, настройкам движения и буззеру. «Терминал COM» содержит ручной ввод и журнал.

В карточке «Автономный заезд» выберите режим, нажмите «Разрешить запуск», затем «Запустить». Режим хранится в EEPROM и также используется при запуске физической кнопкой START. На чистой плате выбран «Поиск и доставка».

- **По линии до груза**. Поставьте робота на линию с опущенными вилами. Откалибруйте белое и чёрное в разделе «Датчики». Робот сразу начнёт следовать линии. После подтверждения сигнала HW-511 он остановит колёса, поднимет вилы и завершит заезд. Для следующего заезда снимите груз, опустите вилы и нажмите «Сбросить».
- **Поиск и доставка**. Поставьте робота в заданный стартовый круг. Прошивка использует маршрут поиска по лучам и доставляет груз в указанную зону второго круга.

Порог линии, Kp/Kd, предел коррекции, время потери линии и подтверждение датчика груза меняются через **«Движение по линии»**. «Применить» меняет параметры до перезагрузки. «Сохранить в EEPROM» записывает применённые значения, которые имеют приоритет над прошивкой. Остальные параметры прошивки доступны через «Настройки», где их можно найти по названию или коду и затем записать через «Прошивка».

## Прошивка при подключённом COM-порте

В разделе «Arduino» → «Прошивка» кнопка «Записать программу по USB»
доступна даже при работающем мониторе порта. При нажатии интерфейс
автоматически завершает чтение/запись монитора, освобождает COM-порт
и предлагает выбрать Arduino для загрузки. Выберите тот же COM-порт в
системном диалоге браузера; при необходимости снова подключите монитор
после записи. Порт нельзя использовать одновременно для мониторинга и
работы загрузчика. Если браузер не поддерживает Web Serial или страница
открыта в небезопасном окружении, используйте Chrome/Edge и отдельный
HTML-файл симулятора или Arduino IDE с экспортированным ZIP.

## Проверка поперечной отметки у груза

Для отметок теперь используется не только фиксированное значение отражения
всех трёх фоторезисторов, а одновременное **повышение черноты** двух
боковых датчиков относительно обычного уровня на продольной линии.
Это помогает, когда боковые датчики стоят на стыке белого и чёрного и
обычно показывают, например, 450–550, а на поперечной полосе 650–750.
Кандидат должен наблюдаться минимум `MARKER_MS` (по умолчанию 20 мс).
Во время подтверждения робот замедляется до `APPROACH_PWM`.

Через «Робот · USB» включите поток. В карточке состояния видны показания
датчиков и флаг «отметка». После успешного подтверждения в терминале появляется
`MARKER CONFIRMED: LOADING ZONE`, а `state` становится `5` (APPROACH).
Это **не команда немедленного разворота**: сначала робот ищет груз
датчиком HW-511, поднимает его при обнаружении, затем отъезжает назад
и разворачивается. Если груз не найден, он всё равно отъезжает и
пытается следующий луч.

Если при пересечении полосы флаг «отметка» остаётся выключенным, сохраните
журнал с показаниями LDR для корректировки порога. Не опускайте
`WIDE_THRESHOLD` вслепую: иначе возможны ложные отметки на обычной линии.
Поперечную линию стоит пересечь с установленной планкой и нормальным
освещением. Фактическая работа зависит от контрастности покрытия и скорости
робота, поэтому нужна проверка на настоящем поле.

## Испытание движения по линии на настоящем роботе

После обновления прошивки повторите калибровку всех трёх фоторезисторов:
- при «белом» образце все три датчика должны целиком находиться над белым;
- при «чёрном» образце — целиком над большим чёрным участком (не на кромке линии);
- при движении средний датчик находится над линией, а боковые могут смотреть на границу чёрного и белого.

### Ход и разворот на шасси 2WD с TT-моторами

Для каждого колеса через «Робот · USB» → «Проба моторов» найдите два значения при штатном питании. Обычная проба показывает PWM, при котором колесо трогается. Проба с толчком показывает PWM, при котором колесо продолжает вращаться. Значения зависят от колеса, нагрузки, напряжения батареи и падения напряжения на L298P. Справочные данные [TT-мотора](https://www.adafruit.com/product/3777) и [L298](https://www.st.com/resource/en/datasheet/l298.pdf) описывают класс деталей. Порог для своего шасси определяют пробой.

В «Скоростях моторов» задайте удерживаемый минимум отдельно для левого и правого колеса. Настройте баланс на прямой, а толчок по PWM, достаточному для пуска обоих колёс. Проверьте значения с грузом и без него. Задание ниже рабочего минимума на непрерывном PWM ограничивается этим минимумом.

- При малой скорости контроллер сохраняет запас для поворота. Если оба колеса упёрлись в свой минимальный PWM, для умеренной коррекции он немного прибавляет внешнему колесу. При сильном уходе линии к одному датчику временно останавливает внутреннее.
- Толчок действует при запуске шасси и при повторном запуске колеса после остановки от 100 мс. Краткая коррекция не запускает новый толчок. Разгон рассчитывается по фактически прошедшему времени. При смене направления команда проходит через ноль.
- Углы в круге рассчитываются по числу шагов по 45°, отдельно для хода с грузом и без. Время масштабируется по эффективному PWM с учётом баланса колёс, рабочих минимумов и длительности ползучих импульсов. Отдельная поправка правого поворота действует на время вращения, а пусковая добавка сохраняется в миллисекундах. После выезда линия подтверждается центральным датчиком.
- При подтверждении отметки зоны или сигнала груза в режиме «По линии до груза» ограничение скорости не превышает скорость движения.
- Для разворота на луче нужны 40 мс без линии под всеми тремя датчиками, затем устойчивая узкая линия под центральным. На подтверждении робот снижает PWM. Если линия устойчиво найдена раньше допустимого времени, робот останавливается с `TURN_EARLY`. При отсутствии подтверждения срабатывает `TURN_TIMEOUT`. По журналу видно, какую из этих границ нужно проверить.

Прошивка не измеряет угол или обороты. `TURN45_MS` и `TURN45_LOADED_MS` калибруются на поле при штатной скорости поворота 85/75 без груза/с грузом. При проверке фиксируйте реальный поворот на полу, с рабочей батареей и обычным грузом. Время обнаружения датчиков и общий тайм-аут заезда остаются обычными миллисекундами. Симулятор использует линейную модель моторов.

Для анализа заезда включите «Телеметрия вкл.». Компактные записи `motion=` содержат этап, ошибку, три сырых показания LDR, PWM на драйвере, командный угол вил, датчик груза, статус груза, ошибку слежения и флаг отметки. Плата пропускает запись, если буфер COM занят, поэтому поток не задерживает опрос линии. Кнопка «Статус» после остановки выводит полный отчёт с нормализованными показаниями, настройками и диагностикой отметок.

## Что проверено

Проверены сборка прошивки для UNO и Nano, автоматические сценарии, ручное управление и экспорт настроек, соответствие встроенных моделей STL и геометрия исправленного узла качалки. C++-адаптер оборудования исполнялся в AVR-эмуляторе с моделями GPIO, EEPROM и серво. Физическая загрузка через браузер и грузоподъёмность ещё требуют испытаний на настоящем роботе.

Симуляция приближённая: она не рассчитывает прочность, массу, сцепление колёс и реальные оптические свойства поля. Поле по картинке — схема для настройки, а не подтверждённые размеры конкурсного поля.

### Калибровка скоростей настоящих моторов по USB

Откройте **Arduino → Скорости моторов**. После прошивки подключитесь к плате, разрешите пробы кнопкой «Разрешить пробы» и проверяйте по одному мотору короткими запусками 50–2000 мс. Команда `jog` для калибровки **подаёт указанный PWM сразу, без плавного разгона, баланса и минимальных порогов** (направление LEFT/RIGHT_REVERSE сохраняется); автоматическое движение продолжает использовать все настройки. В COM-журнал выводятся `JOG START` и `JOG DONE`, а `status` показывает `motor_applied` (фактическую команду на драйвер) и `motor_jog`. Найдите для каждого колеса наименьший ШИМ, при котором оно уверенно трогается при штатном питании. Установите его в качестве **минимального PWM**, затем настройте баланс (1000 = 100%), шесть скоростей маршрута и плавный разгон. Ненулевая команда ниже минимального ШИМ повышается до порога после применения баланса; нулевая команда всегда останавливает колесо. При сильном рыскании снизьте скорость и проверьте корректировку по линии.

«Применить в Arduino» меняет настройки немедленно, но **только до перезагрузки**. «Сохранить в EEPROM» делает их постоянными. Сохранённые значения EEPROM имеют приоритет над параметрами, записанными с новой прошивкой. «Очистить EEPROM моторов» удаляет переопределения; чтобы использовать исходные значения прошивки, перезапустите Arduino.

В терминале доступны `motor set MIN_L MIN_R TRIM_L TRIM_R DRIVE LOADED APPROACH CENTRE TURN TURN_LOADED STEP MS`, `motor save`, `motor clear` и `status`; ручной запуск `jog L R MS` поддерживает -255…255 на колесо и 1…2000 мс. Пробы требуют `arm`, опущенных вил, отсутствия груза, отпущенной кнопки START и остановленного задания. Для проверки вывесьте ведущие колёса и начните с `jog 255 0 500` и `jog 0 255 500` (по одному колесу). Если даже при PWM 255 мотор не вращается, проверьте внешнее питание моторов на клеммах шилда под нагрузкой, общую землю и механическое заклинивание редуктора; USB-питания Arduino недостаточно для ходовых моторов. Панель также попадает в автономный `OFFLINE.html` после автоматической сборки.


### Стартовый импульс и сверхмедленная скорость (экспериментальный режим)

На Arduino → Скорости моторов доступны **раздельные настройки запуска и ползучего движения**. После обновления прошивки нажмите «Подключить» и «Статус». Пока не включены настройки, поведение движения остаётся прежним.

- **Стартовый толчок** `motorKickPwm=145`, `motorKickMs=60` (пример, не калибровка): при пуске шасси или колеса после паузы от 100 мс выдаётся PWM 145 на 60 мс, потом обычная команда. Нулевая команда останавливает мотор; при развороте направления новый толчок не выдаётся. Для отключения задайте PWM или время = 0.
- **Ползучий режим** `motorCrawlLimit=75`, `motorCrawlPwm=110`, `motorCrawlPeriod=160`, `motorCrawlMinOn=16` (всё — пример): при *командном PWM после баланса* ниже 75 игнорируется обычный минимальный PWM и вместо этого подаются короткие импульсы PWM 110 с периодом 160 мс. Длительность включения зависит от величины команды, но не бывает меньше 16 мс. Порог = 0 полностью выключает ползучий режим.
- **Для замедления** установите скорость движения без груза, например, 20–35, затем включите ползучий режим (порог выше выбранного значения) и найдите импульс, который действительно сдвигает колесо. При малой команде нужен достаточно сильный краткий импульс. Движение может быть прерывистым: без энкодеров нет гарантии плавной скорости или одинакового пробега колёс.
- **Проверка**: вывесите колёса; отдельно проверьте точный стартовый порог командой `jog 60 0 1000` (здесь толчок и ползучий режим намеренно **не** действуют); после применённых настроек проверяйте *автоматическое движение* на поле, сначала без груза, с безопасной возможностью остановить робота.
- **Сохранение**: кнопка «Применить толчок и ползучий режим» меняет RAM; «Сохранить всё в EEPROM» сохраняет оба независимых набора настроек. Новые 10 байт лежат по адресам 980–989, не затрагивая SG90 (990+). `motor clear` очищает оба моторных набора; затем перезагрузите Arduino. Старые сохранённые минимальные PWM и баланс сохраняются при обновлении новой версии.
- В терминале аналогично: `motor dynamics 145 60 75 110 160 16`, `motor save`, `status`; порядок значений: PWM толчка, мс толчка, порог ползучего режима, PWM импульса, период (мс), минимальное время включения (мс).

**Ограничения:** реализация действует только на реальной AVR-прошивке; веб-симулятор не моделирует механическое залипание, импульсы и инерцию редукторов. Полевое слежение по линии с включённым ползучим режимом требует отдельной проверки: при очень медленных прерывистых импульсах коррекция двух колёс может быть неравномерной. Для действительно плавной малой скорости надёжнее мотор-редуктор с более высоким передаточным числом, а для стабильного выдерживания скорости — обратная связь от энкодеров.

### Если моторы движутся толчками

Причина — включённый режим `motorCrawlLimit > 0`: он полностью отключает PWM между импульсами. При `motorCrawlPeriod=160`, `motorCrawlPwm=110` и запросе 25 PWM (без балансной поправки) мотор получает PWM 110 примерно 36 мс, затем 124 мс без питания. Это **не непрерывное медленное движение**.

1. **Для плавного хода (предпочтительно)** на USB-панели нажмите «Плавно: без пауз», затем «Применить толчок и ползучий режим». Программная команда `motor dynamics 145 60 0 110 160 16` даёт тот же результат. Стартовый толчок остаётся, периодическое отключение пропадает. По одному колесу найдите минимальное *устойчивое* PWM при движении под реальной нагрузкой, уменьшите `motorMinLeft` / `motorMinRight` до этих значений, затем подберите скорости движения. Если минимум 70 сильно разгоняет колёса, можно пробовать 40–60, но не рассчитывайте, что любой мотор будет стабильно работать на таком значении.
2. **Для эксперимента с более частыми импульсами** нажмите «Частые импульсы (опытный режим)» и «Применить...». Пример `motor dynamics 145 60 75 110 40 8` уменьшает период до 40 мс вместо 160 мс. С этой версии допустим период от 30 до 255 мс. Это может уменьшить заметность рывков благодаря инерции, но при коротких импульсах возможна остановка моторов под нагрузкой; начинать испытания с вывешенными колёсами.
3. Нажимайте «Сохранить всё в EEPROM» только после испытания. Новые значения **не применяются автоматически** при обновлении прошивки; старые сохранённые 160 мс остаются прежними.

Без энкодеров и подходящего передаточного отношения редуктора нельзя одновременно гарантировать очень низкую скорость, ровную езду и точные повороты только с помощью PWM.

### Измерение минимального PWM после пускового толчка

В **Arduino → Проба моторов** есть галочка «Сначала пусковой толчок, затем удержание заданного PWM». Задайте рабочий PWM для левого и/или правого мотора (например, 30), длительность всей пробы (1000–2000 мс), PWM толчка (например, 145), длительность толчка (например, 60 мс). Сначала «Подключить» и «Разрешить пробы», вилы внизу, груз снят; для испытания по одному колесу нажмите «Только левый» или «Только правый». Начинайте с вывешенными колёсами, затем повторите на поверхности под реальной нагрузкой.

**Как проверять:** сначала установите рабочий PWM 70–80 и убедитесь, что после толчка мотор продолжает вращаться. Уменьшайте рабочий PWM шагами 5–10 и повторяйте пробу. Когда колесо останавливается после перехода со стартового импульса, увеличьте удерживаемый PWM до устойчивого значения с запасом. Повторите для другого колеса, на полу и с нужной нагрузкой. Так подбирается **минимальный удерживаемый PWM**, который может быть значительно меньше **PWM запуска из состояния покоя**.

Команда в терминале: `jogkick L R TOTAL_MS KICK_PWM KICK_MS`, например `jogkick 30 0 1500 145 60`. Первый отрезок 60 мс — PWM 145; оставшиеся 1440 мс — ровно PWM 30. Если заданный рабочий PWM больше стартового, стартовый этап его не уменьшит. Нулевое колесо остаётся выключенным. Для сравнения обычный `jog 30 0 1500` подаёт PWM 30 без пуска. Оба режима **игнорируют** минимальный PWM, баланс, плавный разгон и импульсный ползучий режим. Параметры проб **не сохраняются в EEPROM** и не меняют настройки автономного движения. Команда `stop`, нажатие START, обнаружение недопустимого состояния и окончание таймера обеспечивают остановку согласно штатным защитам.

В логе видно `JOG KICK START`, `JOG HOLD` и `JOG DONE`; `status` сообщает `motor_applied` (фактическая команда на драйвер) и `motor_jog_stage`. **Прошивка не умеет измерить, вращается ли вал на самом деле:** без энкодера порог удержания определяется визуально, звук мотора сам по себе недостаточен. Найденное значение можно использовать для настройки минимального PWM каждого колеса при непрерывном режиме (порог ползучего режима 0).
